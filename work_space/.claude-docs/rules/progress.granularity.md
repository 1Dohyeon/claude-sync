# progress 작업 단위 크기 기준

progress의 **큰/중간/작은 작업을 어느 크기로 끊을지**만 정의한다.
(파일 배치·이름·이관·합작 규칙은 GLOBAL CLAUDE MD의 `.claude-docs` 섹션 참고.)

> 크기 기준은 스택마다 다르므로 workspace가 조정한다. 아래는 **백엔드 기준**.

## 계층별 크기 (백엔드 기준)

| 계층    | 이름                | 크기                                   |
| ------- | ------------------- | -------------------------------------- |
| `#`     | 큰 작업 (작업 목표) | 여러 모듈에 걸치더라도 **하나의 목표** |
| `##`    | 중간 작업           | **하나의 모듈**                        |
| `- [ ]` | 작은 작업           | **하나의 파일 또는 함수**              |

## 끊는 기준

- 큰 작업 제목에 "**~와/및 ~**"(and)가 들어가면 목표가 둘이라는 신호 → 나눈다.
- **상한**: 작은 작업(체크박스)이 대략 7개를 넘고 성격이 갈리면 중간 작업을 나눈다.
- **하한**: 한두 개짜리로 독립 가치가 없으면 별도로 만들지 말고 흡수한다.

## 예시 (백엔드)

- ✅ `# 결합 수정 기능` + `## admin/combine-conditions` + `- [ ] 결합 수정 PUT 추가`
- ❌ `# 결제`와 `# 인증`을 한 파일에 → 목표 둘이므로 분리
