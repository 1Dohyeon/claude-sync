# 개발 태스크 작업 규칙

코드를 작성·수정하는 작업에 적용한다. 저자 개인의 개발 워크플로다 — 포크했다면 이 파일을 자기 방식으로 바꾸고 `CLAUDE.md`의 ROUTING 표를 그에 맞게 고치면 된다.

## 함께 적용되는 규칙

**개발 태스크 작업은 항상 `~/.claude/rules/worklog.md`와 같이 적용된다.** ROUTING 표에서 이 파일만 매칭됐더라도 `worklog.md`를 반드시 함께 Read 한다.
기록 위치·이어받기·설계 문서·진행 기록·완료 처리는 전부 그쪽 규칙이고, 이 파일에는 없다.

`git-workflow.md`는 다르다. **브랜치 생성·worktree·커밋·push 단계에 도달하면 그때** Read 한다.
설계 문서만 쓰는 단계에서 절차 문서를 미리 로드하지 않는다.

## 브랜치·worktree

결정 규칙만 여기 둔다. 절차(remote 브랜치 선생성, upstream 검증, 의존성 설치)는 `~/.claude/rules/git-workflow.md`에 있다.

- 대상 브랜치 == 현재 체크아웃이면 아무것도 만들지 않고 그대로 이어서 작업한다.
- 그 외(신규든 기존이든)는 항상 worktree로 분리한다 — 메인 작업 폴더가 베이스 브랜치라 "비어 있다"는 것은 거기서 작업할 이유가 되지 않는다.
- 메인 작업 폴더(`.git/`이 있는 원본 체크아웃)에서 브랜치를 만들거나 다른 브랜치로 전환하지 않는다.
- 설계 문서 작성보다 worktree 생성을 먼저 하지 않는다.
- 사용자 승인 없이 worktree를 만들지 않는다.
- 이어받을 task의 브랜치가 현재 체크아웃과 다르면 `git checkout`하지 않고 worktree로 진입해서 읽는다.
