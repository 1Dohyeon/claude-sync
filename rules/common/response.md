# RESPONSE RULE

적용 범위: 모든 답변과, 새로 쓰거나 고치는 문서.

## 언어

- 대답은 항상 한국어로 쓴다. 사용자가 영어로 요청해도, 직전에 읽은 도구 출력·문서·로그가 영어여도 마찬가지다. 코드·명령·오류 메시지 원문 인용만 원문 그대로 둔다.
  - 사유: 영어 자료를 읽은 직후에는 답변이 영어로 넘어가기 쉽다.

## 오류 보고

- "오류가 있다"라고만 쓰지 않고 오류 메시지 원문을 함께 붙인다.
  - 사유: 원문이 있어야 사용자가 직접 원인을 판단하거나 검색할 수 있다.

## 표기

- 엠대시(`—`)를 쓰지 않고 쉼표, 콜론(:), 괄호, 붙임표(-)로 대신한다. 자동 메모리 파일(`MEMORY.md`의 목록 줄 포함)에도 적용하며, 하네스 기본 형식이 엠대시를 쓰더라도 `- [제목](파일.md): 설명`처럼 콜론으로 쓴다.
  - 사유: 유니코드 폭 분류가 Ambiguous라 한국어 로캘 터미널에서는 2칸으로 표시될 수 있어 정렬이 어긋나고, UTF-8로 3바이트라 붙임표(1바이트)보다 크다. md 파일은 `hooks/md-no-em-dash.sh`가 막지만 답변 본문은 막지 못한다.
- 범위를 물결표로 쓸 때는 `2\~3`처럼 물결표 앞에 백슬래시를 붙인다. 코드 블록과 인라인 코드 안에서는 붙이지 않는다.
  - 사유: 마크다운은 한 문단 안의 물결표 두 개 사이를 취소선으로 처리해서, 범위 표기가 두 번 이상 나오면 그 사이 글자에 취소선이 그어진다.
- 줄바꿈은 문장이 끝난 뒤에만 한다. 산문 문단은 2\~3문장으로 묶고, 리스트 항목은 한 문장씩 줄을 바꾼다. 대상 저장소가 일정 글자 수로 줄을 끊는 컨벤션이면 그것을 따른다.
  - 사유: 문장 중간에서 끊으면 읽기 어렵고, 고칠 때 줄 단위 diff가 지저분해진다.

## 답변 순서

- 선택·결정을 묻는 질문("뭐가 나아?", "이렇게 할까?")에는 결론과 추천을 먼저 쓰고 근거를 뒤에 쓴다.
- 설명·이해를 묻는 질문("왜 그래?", "무슨 일이야?")에는 배경을 먼저 짚고 결론으로 이어 간다.
  - 사유: 결정할 때는 결론이 먼저 필요하고, 이해할 때는 맥락 없이 던진 결론이 납득되지 않는다.
