# worklog 기록 규칙

작업 기록·이어받기·완료 처리 규칙이다. 주로 개발 태스크를 주제로 문서를 기록한다.(개발 고유 규칙은 [`~/.claude/rules/development.md`](./development.md))

## 위치

- 기록 공간은 **어느 기기에서든 `~/.claude/worklog/`** 다.
- clone 경로가 기기마다 달라도 심링크가 흡수하므로 실제 clone 경로를 찾아 나서지 않는다.
  - `~/.claude/worklog` 자체가 없으면 사용자에게 알린다. 임의로 만들거나 다른 경로로 우회하지 않는다.
  - 사용자에게 연결을 원하는지 물어본다. 원하면 [`~/.claude/rules/worklog-setup.md`](./worklog-setup.md)를 Read해서 따른다.
- `worklog`는 주로 개발 작업에서 사용된다. 따라서 `worklog/<repo>/` 경로에 프로젝트별 작업 기록을 저장한다.
  - `<repo>`=`git remote get-url origin`의 마지막 세그먼트(`.git` 제외). 매번 새로 계산한다(이전 세션 값을 재사용하지 않는다).
  - 개발 작업이 아니라서 `git`이 없다면, `<repo>` 대신 쓸 폴더명을 사용자에게 직접 물어본다. 추측하지 않는다.

## 문서 두 종류

task 기록은 보고서와 작업 문서로 나뉜다. 같은 사실을 두 곳에 쓰지 않도록 각자 **쓰지 않는 것**을 정해두었다.

| | 파일 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|---|
| 보고서 | `tasks/<대상 브랜치>.md` | 산문. 왜·이전 상태·바꿀 내용·효과·파급 범위 | 체크박스, 커밋 해시, 행 번호, 검증 로그, 파일 경로 나열 |
| 작업 문서 | `tasks/<대상 브랜치>.work.md` | 체크리스트, `파일:심볼`, 진행, 검증 | 배경 서술 (보고서를 참조만 한다) |

- **보고서는 항상 만든다.** 사람이 읽고 승인하는 문서이며, 이것이 곧 작업 컨벤션의 "보고"다.
- **작업 문서도 보고서와 함께 항상 만든다.** 둘은 짝이므로 한쪽만 있는 상태를 두지 않는다. 세션이 길어질지는 시작할 때 알 수 없어서, 넘길 때 만들기로 하면 놓치게 된다. 만들어 두면 `## 작업 목록`이 곧 할 일 목록이 되고, 세션 시작 훅([hooks/load-overview.sh](../hooks/load-overview.sh))이 이 파일을 컨텍스트에 넣어 준다.
- 브랜치를 안 파는 간단한 작업은 보고서를 만들지 않으므로 작업 문서도 만들지 않는다. 짝을 맞출 대상이 애초에 없다.
- **보고서는 사실이 바뀌면 덮어쓴다.** 정정 문장이나 `## 설계 변경` 같은 섹션을 덧붙이지 않는다. 보고서는 항상 현재의 계획 하나만 보여준다.
- `## ` 제목은 템플릿에 고정되어 있고 훅([hooks/check-task-doc.sh](../hooks/check-task-doc.sh))이 검사한다. 새 제목을 만들지 않는다.

## 작업 컨벤션

worklog를 거치는 모든 작업은 설계, 보고, 진행, 검증, 완료 순으로 진행한다.

### 시작

- `worklog/<repo>/overview.md`가 있으면 세션 첫 요청에서 Read하고 시작한다(없을 수 있다, 훅이 세션 시작 후 자동 실행).
  - `<branch>`=`git rev-parse --abbrev-ref HEAD`. 매번 새로 계산한다(이전 세션 값을 재사용하지 않는다).
  - 없으면 첫 작업이므로 공간을 만들지 사용자에게 확인한다.
  - `tasks/<branch>.md`가 있으면 이어받고, 없으면 아래 "설계" 규칙대로 새로 만든다. `.work.md`가 함께 있으면 그쪽 `## 진행`의 마지막 회차부터 이어받는다.

### 설계

결과물을 남기는 규칙이다.

- 보고서와 작업 문서는 `/task <대상 브랜치>`로 함께 만든다. 템플릿을 그대로 복사하므로 골격을 손으로 짜지 않는다.
  - `<대상 브랜치>`는 지금 체크아웃된 브랜치가 아니라 **작업할 브랜치**다. 브랜치가 아직 없어도 그대로 진행한다. 경로는 폴더명일 뿐이다.
  - 커맨드를 쓸 수 없는 상황이면 [`~/.claude/templates/task.md`](../templates/task.md)와 [`~/.claude/templates/task-work.md`](../templates/task-work.md)를 `cp`로 복사한다. 내용을 새로 짜지 않는다.
  - 이때 작업 문서는 `## 작업 목록`만 채운다. `## 진행`은 세션을 끊을 때, `## 검증`은 확인한 뒤에 쓴다.
- 경로를 추측해서 쓰지 않고 기본값을 제시해서 확인받는다.
- 브랜치를 안 파는 작업은 간단한 작업이므로 굳이 기록을 남기지 않는다.

### 보고

설계 문서의 경로·내용을 사용자에게 제시하고 확인받는 단계다(위 "설계"의 확인 규칙 참고).

### 진행

- 세션이 미완료로 끝나면 `tasks/<대상 브랜치>.work.md`의 `## 진행` 아래에 회차를 덧붙여 "한 것 / 막힌 것 / 다음 할 것"을 적는다. 파일은 설계 단계에서 이미 만들어져 있다.
- 작업 목록의 체크박스는 항목이 끝날 때마다 갱신한다.
- 앞 회차의 기록은 고치지 않는다. 덧붙이기만 한다.
- 방향이 바뀌었으면 보고서를 덮어쓴다. 작업 문서에 "설계 변경" 기록을 남기지 않는다.
- 미완료 문서를 `done/`으로 옮기지 않는다.

### 검증

완료 처리 전에 작업 문서의 `## 검증`에 무엇을 어떻게 확인했는지 남긴다. 보고서를 만들지 않은 간단한 작업은 대화로 보고한다.

### 완료

사용자가 통과로 확인한 뒤에만 수행한다. 사용자 허락 없이 `done/`으로 옮기지 않는다.

- 옮기기 전에 작업 문서 끝의 `## 완료`를 채운다.
- `done/`으로 이동한다 (1-depth 평탄 유지, 하위 폴더를 만들지 않는다, 브랜치명의 `/`는 `-`로 치환). 보고서와 작업 문서를 **둘 다** 옮긴다.
  - 브랜치 작업 → `tasks/done/<branch>-YYYYMMDD.md` · `tasks/done/<branch>-YYYYMMDD.work.md`
  - 날짜-슬러그 작업 → 파일명 그대로 `tasks/done/<YYYYMMDD>-<슬러그>.md` (날짜를 또 붙이지 않는다)

## 주의

- task 문서는 worklog 안에만 만든다. 작업 중인 코드 저장소 안에는 만들지 않는다(남의 저장소를 오염시킨다).
- worklog는 git 저장소로 clone되어 있다고 전제한다. 커밋·푸시는 세션 종료 훅([hooks/save-docs.sh](../hooks/save-docs.sh))이 처리하므로, Claude는 Read/Write만 한다.

## 중단

완료가 아니라 더 이상 진행하지 않기로 한 작업(프로젝트 자체가 중단된 경우 등)은 `done/`이 아니라 `tasks/stalled/`로 옮긴다. 파일명 규칙은 완료와 동일하다 — 사용자 허락 없이 옮기지 않는다.

## 과거 작업 참조

- 이전에 한 작업을 찾을 때는 `~/.claude/worklog/<repo>/tasks/done/`·`tasks/stalled/`를 Grep한다 — 기억에 의존하지 않는다.
