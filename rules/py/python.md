# PYTHON RULE

적용 범위: Python 파일을 다룰 때. 저장소 규칙(CLAUDE.md, `pyproject.toml`의 도구 설정, 기존 코드의 다수 양식)이 다르게 정해 두었으면 그것을 따른다.

## 버전

- 라이브러리·프레임워크 API를 쓰기 전에 `pyproject.toml`과 lockfile(`uv.lock`, `poetry.lock`, `requirements*.txt`)에서 실제 버전을 확인하고 그 버전 기준으로 쓴다. 기억에 있는 최신 문법을 기본값으로 쓰지 않는다.
  - 사유: 학습 데이터의 문법은 프로젝트가 쓰는 버전보다 옛것이거나 새것일 수 있어, 그 버전에 없는 API를 쓰게 된다.
- 문법은 `requires-python`(없으면 `.python-version`)이 정한 최저 버전에 맞춘다. 예를 들어 3.10 미만이면 `X | None` 대신 `Optional[X]`를 쓴다.
  - 사유: 최저 버전보다 새 문법을 쓰면, 그 버전으로 실행하는 환경에서 import 단계부터 실패한다.
- 패키지 호환성은 기억으로 판단하지 않는다. 패키지 매니저의 해석 결과(`uv lock`, `pip check` 등)와 테스트 결과로 판단한다.
  - 사유: Python 버전, 패키지, 하위 의존성의 조합은 너무 많아 외울 수 없고, 정확한 정보는 패키지 매니저가 이미 갖고 있다.

## 타입

- 모듈 밖에서 쓰는 함수와 메서드에는 매개변수와 반환 타입을 적는다.
<!-- 사유: 공개 함수의 타입이 없으면 구현을 고칠 때 호출부와의 계약이 말없이 바뀌고, 타입 검사기도 잡지 못한다. -->
- `Any`를 쓰지 않는다. 외부 입력은 검증한 뒤 구체적인 타입으로 다룬다.
<!-- 사유: Any는 타입 검사를 꺼서, 검사 단계에서 잡혀야 할 오류가 실행 중에 드러난다. -->

## 비밀값

- API 키와 토큰을 코드에 쓰지 않는다. 환경 변수에서 읽고, 값이 없으면 시작 시점에 오류를 낸다.
<!-- 사유: 코드에 쓴 키는 커밋 히스토리에 남아, 나중에 지워도 저장소를 받은 사람 누구나 볼 수 있다. -->
- 로그에 자격 증명, 쿠키, Authorization 헤더, 토큰을 남기지 않는다.
<!-- 사유: 로그는 코드보다 넓게 공유되고 오래 보관되어, 거기 남은 값은 유출 경로가 된다. -->

## 비동기 웹 프레임워크(FastAPI 등)

- `async def` 엔드포인트 안에서 블로킹 호출(`requests`, 동기 DB 세션, 동기 파일·네트워크 I/O)을 하지 않는다.
  - 사유: 블로킹 호출은 이벤트 루프를 멈춰, 그 요청뿐 아니라 같은 프로세스의 다른 요청까지 기다리게 만든다.
- 응답 모델에 비밀번호, 비밀번호 해시, 액세스·리프레시 토큰을 넣지 않는다.
<!-- 사유: 응답 모델에 들어간 필드는 그대로 클라이언트에 전달된다. -->
