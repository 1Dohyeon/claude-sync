# 기존 기능 수정 작업 규칙

[`SKILL.md`](./SKILL.md)의 공통 규칙 위에서, 유형이 동작 변경·버그 수정·리팩터링일 때 따르는 규칙이다. 세 유형 모두 이미 있는 동작을 건드리므로 출발점이 같다.

## 공통 출발점

- 고치기 전에 지금 동작을 코드나 실행으로 먼저 확인한다. 기억이나 추측으로 대신하지 않는다.
- 바뀌는 심볼의 호출부를 먼저 파악한다.

## 동작 변경

- 기존 테스트를 새 요구에 맞게 먼저 고치고, 그 테스트가 통과하도록 구현을 바꾼다.

## 버그 수정

- 버그를 재현하는 테스트를 먼저 작성한다.
- 재현한 뒤 원인을 좁히고 나서 고친다. 고친 뒤 재현 테스트가 통과하는지 확인한다.
- 원인을 특정하지 못했으면 증상만 가리는 수정을 하지 않는다. 멈추고, 확인한 것과 모르는 것을 나눠서 보고한다.

## 리팩터링

- 전후로 테스트가 통과하는지로 검증한다.
