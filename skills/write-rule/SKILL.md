# 규칙 작성

`rules/`에 규칙을 만들거나 고칠 때의 절차다. 형식은 [`templates/rules.md`](../../templates/rules.md)를 따른다. 작성하기 전에 이 템플릿을 Read한다.

## 1. rule에 맞는지 가른다

rules는 매 세션(또는 일치하는 파일을 다룰 때마다) 자동으로 주입된다. 그래서 항상 지켜야 하는 짧은 기준만 rule로 둔다. 아래에 해당하면 rule로 만들지 않고, 더 맞는 곳을 제안한다.

| 내용 | 더 맞는 곳 |
| --- | --- |
| 특정 작업에서만 쓰는 절차(리뷰 순서, 배포 단계 등) | 스킬 |
| 말로 지시해도 자주 어겨서 기계적으로 막아야 하는 것 | 훅(`hooks/`, 예: `md-no-em-dash.sh`) |
| 경로처럼 기기마다 다른 값 | `rules/common/environments.md` |
| 특정 저장소에서만 맞는 규칙 | 그 저장소의 `CLAUDE.md`나 `.claude/rules/` (사용자에게 확인한 뒤) |
| 이번 대화에서만 필요한 것 | 만들지 않는다 |

- 사유: rule은 주입될 때마다 컨텍스트를 차지하고, 한 번 들어가면 모든 세션의 행동을 바꾼다. 맞지 않는 내용을 rule로 두면 비용은 계속 들고 효과는 작다.

## 2. 기존 규칙과 겹치는지 확인한다

`rules/`와 `CLAUDE.md`에서 같은 주제를 검색한다. 겹치는 규칙이 있으면 새 파일을 만들지 않고 그 파일에 항목을 더하거나 고치는 것을 제안한다. 내용이 서로 어긋나면 어느 쪽을 남길지 사용자에게 묻는다.

- 사유: 같은 주제가 두 파일에 나뉘면 한쪽만 고쳐져 서로 어긋나기 쉽다.

## 3. 위치와 로드 조건을 정한다

| 적용 대상 | 위치 | 로드 조건 |
| --- | --- | --- |
| 어떤 작업에서든 지켜야 하는 것 | `rules/common/<주제>.md` | frontmatter 없음(항상 로드) |
| 특정 언어·파일을 다룰 때만 지켜야 하는 것 | `rules/<언어 약어>/<주제>.md` (예: `ts/`, `py/`) | `paths:`에 그 파일의 glob |

- 언어 폴더가 이미 있으면 그 안에 둔다. 같은 언어의 규칙은 파일 하나에 모으는 것을 기본으로 한다.
- `paths:`는 그 규칙이 실제로 필요한 파일만 잡는다. 너무 넓게 잡으면(예: `**/*`) 항상 로드되는 것과 다르지 않다.
- 파일 이름은 주제를 한 단어로 짓는다(예: `memory.md`, `response.md`). 스킬 이름과 헷갈리지 않게 한다.
- 사유: 로드 조건이 곧 이 규칙의 트리거다. 항상 로드할 필요가 없는 규칙에 `paths:`를 붙이면 상관없는 세션의 컨텍스트를 아낄 수 있다. 다만 path 조건이 있는 규칙은 compaction 뒤 일치하는 파일을 다시 다룰 때까지 빠지므로, 승인이나 완료 확인처럼 언제나 지켜야 하는 규칙에는 붙이지 않는다.

## 4. 초안을 쓰고 확인받는다

템플릿 형식으로 초안을 쓴다.

- 맨 위에 적용 범위를 한 줄로 적는다.
- 규칙 문장마다 사유를 붙인다. 사용자가 사유를 말하지 않았으면 추측해서 채우지 않고 묻는다.
  - 모델이 원래 하던 행동과 다른 규칙은 `- 사유:` 줄로 쓴다.
  - 모델이 원래 그렇게 하는 당연한 규칙은 항목 바로 아래 `<!-- 사유: ... -->` 주석으로 쓴다. 주석은 줄 맨 앞에 들여쓰지 않고 쓴다. 들여쓰면 주입될 때 제거되지 않는다. 어느 쪽인지 애매하면 `- 사유:` 줄로 쓴다.
- 항목이 적으면 항목 이름 없이 불릿만 쓴다.
- 템플릿의 작성 규칙 주석은 옮기지 않는다.

초안과 함께 위치, 로드 조건, 1~2단계에서 판단한 내용을 보고하고, 사용자가 확인한 뒤에 파일을 만든다.

- 사유: rule은 이후 모든 세션에 영향을 주므로, 문구 하나도 사용자가 확인한 것만 들어가야 한다. 사유는 모델이 읽어야 비슷한 경우까지 적용하지만, 당연한 규칙의 사유는 효과 없이 컨텍스트만 차지한다. 줄 맨 앞의 HTML 주석은 주입 전에 제거되고, 리스트 항목 안에 들여쓴 주석은 제거되지 않는 것을 실제 세션에서 확인했다.

## 5. 만들고 확인한다

1. 파일을 만들거나 고친다.
2. 로드되는지 새 세션으로 확인한다.
   - 항상 로드: 다른 폴더에서 `claude -p`로 세션을 열고, 로드된 rules 파일 목록에 새 파일이 있는지 묻는다.
   - `paths:` 조건: 일치하는 파일 하나를 Read하게 한 뒤, 규칙 제목이 컨텍스트에 있는지 묻는다.
3. 다른 문서가 이 규칙 파일을 가리켜야 하는지 판단한다. rules는 자동으로 주입되므로, 스킬이나 문서에서 일부러 가리킬 필요는 없다. 예외를 정하는 문장처럼 규칙 이름을 꼭 알아야 하는 곳만 단계 이름으로 가리킨다.
4. 무엇을 만들었는지와 로드 확인 결과를 보고한다.

- 사유: 사용자 rules의 하위 폴더와 `paths:` 동작은 문서에 다 나와 있지 않아서, 실제 세션에서 확인해야 한다.
