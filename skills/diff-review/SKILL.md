# 커밋 전 리뷰

아직 커밋하지 않은 변경이 대상이다. 판단할 것은 "이대로 커밋해도 되는가"다.

## 범위

범위는 "지금 커밋하면 올라갈 것 전부"다. 추적 중인 수정과 추적되지 않은 새 파일을 모두 본다. 되묻지 않는다.

`git diff HEAD`는 추적되지 않은 파일을 담지 않으므로, 스냅샷을 뜨기 전에 저장소 루트에서 새 파일을 intent-to-add 한다.

```sh
git add -N .
```

```sh
git diff HEAD
```

이 출력이 스냅샷이다. 뜬 뒤 인덱스를 되돌린다.

```sh
git reset
```

- `.gitignore` 대상은 `git add -N`이 무시하므로 자동으로 범위 밖이다. 커밋에 안 올라갈 파일은 gitignore에 있어야 한다.
- `git reset`은 인덱스만 되돌리고 워킹트리는 건드리지 않는다. `-N`은 내용을 스테이징하지 않으므로 실제 커밋에 영향이 없다. 리뷰 전에 스테이징해 둔 것이 있으면 함께 풀리니 커밋 전에 다시 add 한다.
- 무엇이 범위에 들었는지는 `git status --porcelain`으로 확인한다. 표시만 하고 되묻지는 않는다.

셸 변수를 쓰지 않고 명령을 리터럴로 쓴다. Bash 호출 사이에는 셸 상태가 남지 않는다. 단일 명령으로 유지한다. `&&`·`;`·`|`로 엮으면 allowlist의 접두 규칙에 걸리지 않아 매번 승인 프롬프트가 뜬다.

## 축

두 축만 부른다.

- [`logic-reviewer`](../../agents/logic-reviewer.md)
- [`convention-reviewer`](../../agents/convention-reviewer.md)

**부르기 전에 요구사항을 먼저 확보한다.** worklog의 현재 브랜치 task 문서에서 계획 섹션을 꺼내 요구사항 본문으로 두 에이전트에 실어 넘긴다. 문서가 없으면 부르지 말고 사용자에게 요구사항을 먼저 묻는다. 확보 절차는 [`review-common/verify.md`](../review-common/verify.md)의 요구사항 확보에 있다.

여기서 요구사항은 지적을 만드는 근거가 아니라 **오탐을 거르는 근거**다. 공통부 검증의 "요구사항에 명시된 동작은 버린다"가 그것으로 작동한다.

화면에 닿는 파일이 있으면 [`qa-reviewer`](../../agents/qa-reviewer.md)를 부록으로 함께 부른다. 방금 짠 화면을 브라우저에서 무엇부터 볼지가 이 시점의 실제 필요다.

아키텍처·테스트·요구사항 축은 여기서 부르지 않는다. 커밋 직전은 기능이 절반만 짜인 상태일 수 있기 때문이다. 아키텍처 축은 미완성을 구조 결함으로 오인하고, 요구사항 축은 아직 안 만든 것을 누락으로 자리만 잡아둔 코드를 어긋남으로 올린다. 테스트도 아직 쓰지 않은 시점이 정상이라 "없다"는 지적만 쌓인다. 셋 다 [`branch-review`](../branch-review/SKILL.md)가 완성된 단위에서 본다.

## 이어서

[`review-common/verify.md`](../review-common/verify.md)를 읽고 요구사항 확보부터 출력까지 그대로 진행한다. 요구사항은 사용자에게 먼저 묻지 않고 worklog의 현재 브랜치 task 문서부터 본다.
