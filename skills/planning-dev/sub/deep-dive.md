# 깊은 분석

사용자가 요청하거나 계획 문서를 보강할 때만 쓴다. 기본 흐름에서는 쓰지 않는다. 요구사항 원문은 [`analyze-task.md`](./analyze-task.md)의 "요구사항 확보"대로 먼저 확보한다.

## 과거 유사 태스크 확인

먼저 `AskUserQuestion`으로 "과거 유사 태스크도 살펴볼까요?"를 예/아니오로 묻는다. 새 기능처럼 선례가 없는 태스크에서도 단어가 조금 겹친 어중간한 후보가 나와 분석을 엉뚱한 쪽으로 끌 수 있어서, 선례가 있을 법한지는 사용자가 정한다. 아니오면 아래 검색을 모두 건너뛴다.

예면 과거 계획과 PR·커밋을 각각 찾는다. 결과는 따로 나오며 섞지 않는다. 동료가 한 일이나 계획 문서를 쓰기 전의 일은 PR·커밋에서만 잡힌다.

- `<repo>`는 지금 작업 중인 저장소 이름이다. 계획 문서 경로의 `{repo}` 자리에 쓰는 이름과 같다.
- `<요구사항 원문 요약>`은 원문 전체가 아니라 핵심 주제어 몇 개로 줄인 것이다. 원문을 그대로 넣으면 신호가 흐려진다.

### 과거 계획: 찾는 순서

앞 순서를 쓸 수 없을 때만 다음 순서로 넘어간다.

1. **앱의 검색**: 세션을 연 앱이 세션 시작 안내로 과거 계획 검색 명령(검색, 읽기)을 알려 줬으면 그 명령으로 찾는다. 안내가 없거나, 모든 질의가 쓸 수 없다는 안내나 실패 문구로 끝나면 2로 넘어간다.
2. **`tasksim.py`**: `~/plans/`의 진행 중·완료 폴더에서 비슷한 계획을 찾는다. 라이브러리가 없다는 등의 이유로 건너뛰면 3으로 넘어간다.
3. **`~/plans` 직접 검색**: `~/plans/{owner}/{repo}/`와 `~/plans/done/{owner}/{repo}/`에서 요구사항의 핵심 단어를 `Grep`으로 찾는다.

### 과거 계획: 누가 찾는가

이 저장소 최상위 `.env`(git 제외)에 API 키가 있으면 스크립트가 1, 2를 하고, 관련 부분을 원문 그대로 발췌해 돌려준다. 발췌는 그 키로 Messages API를 불러서 하므로, 메인 대화의 청구처와 따로 청구된다.

```sh
python3 ~/.claude/skills/planning-dev/hooks/plan_research.py --repo <repo> --summary "<요구사항 원문 요약>" [--search-cmd "<검색 명령>" --read-cmd "<읽기 명령>"]
```

- `--search-cmd`, `--read-cmd`는 1의 명령이 있을 때만 넘긴다. 안내의 명령 줄에서 질의나 식별자 자리와 그 뒤의 선택 인자를 뺀 앞부분을 넘긴다.
- 결과가 `검색 실패`이면 그 이유를 사용자에게 알리고, 메인이 3을 한다.
- 종료 코드가 3(API 키나 `anthropic` 패키지 없음)이면 그 사실을, 4(API 호출 실패)면 오류 문구를 그대로 사용자에게 알리고, 메인이 1부터 직접 찾는다.

메인이 직접 찾을 때는 순서마다 아래처럼 연다.

- 1: 짧은 질의 몇 개로 검색하고, 관련 있어 보이는 계획만 읽기 명령으로 연다.
- 2: `tasksim.py <repo> <요구사항 원문 요약>`을 돌리고, 유사도가 눈에 띄게 높은 폴더만 `requirements.md`를, 없으면 `tasks.md`를 `Read`로 연다.
- 3: `Grep`에 걸린 폴더의 `requirements.md`를, 없으면 `tasks.md`를 연다.

### 과거 계획: 결과 다루기

- 발췌는 해석이 아니다. 이번 작업에 무엇을 적용할지는 메인이 판단하고, 더 필요하면 발췌에 적힌 식별자로 원문을 직접 연다.
- 열어 보니 무관하면 버린다.
- `~/plans`에 그 저장소 폴더가 없으면 "이 기기에 이 저장소의 과거 계획이 없다"고 알린다. `~/plans` 자체를 읽을 수 없을 때만 "과거 계획을 검색하지 못했다"고 알린다. 어느 경우든 "과거 유사 태스크가 없다"로 바꿔 말하지 않는다.

### PR·커밋

메인이 직접 돌린다.

```sh
python3 ~/.claude/skills/planning-dev/hooks/prsim.py <저장소 경로> <요구사항 원문 요약>
```

- `prsim.py`는 저장소의 merge된 PR을 본다(`gh`를 못 쓰거나 PR이 없으면 커밋).
- `<저장소 경로>`는 지금 작업 중인 저장소의 경로다. 저장소 안에서 돌리면 `.`이다.
- 라이브러리가 없거나 git 저장소가 아니어서 건너뛴다는 안내가 나오면 그대로 다음 단계로 간다. 실패로 취급하지 않는다.
- 유사도가 낮은 결과(0에 가까움)까지 끌어오지 않는다. 눈에 띄게 높은 것만 PR은 `gh pr view <번호>`로, 커밋은 `git show --stat <해시>`로 연다. 열어 보니 무관하면 버리고, 관련 있으면 무엇을 했는지 한두 줄로 남긴다.
- 이건 `cochange.js`(`impact-analyst`가 쓰는, git 커밋 기반 파일 동반 관계)와 다른 도구다. 이건 텍스트 유사도로 업무 단위 선례를 찾는다.

### 반영

찾은 게 있으면 분석에 "참고: 과거 유사 태스크"로 반영한다. [`analyze-task.md`](./analyze-task.md)의 서브에이전트를 부를 때 호출 프롬프트에 함께 싣고, PR·커밋이면 변경 파일 목록도 싣는다. `impact-analyst`가 그 목록을 `cochange.js` 입력으로 쓸 수 있다. 서브에이전트를 부르지 않는 규모이면 메인이 분석에 직접 반영한다. 없으면 언급하지 않는다.
