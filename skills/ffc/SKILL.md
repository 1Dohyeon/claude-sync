# feedback for claude

Claude가 작업 규칙을 어긴 사례를 어느 배경에서 무엇을 잘못했는지만 짧게 남기는 로그다. 원인 분석과 보강 방안은 쓰지 않는다. 보강은 이 로그를 읽는 별도 작업이 맡는다.

## 언제 쓰는가

- 사용자가 `/ffc`를 부르거나 기록하라고 할 때.
- 사용자가 Claude의 행동이 규칙과 다르다고 지적할 때. "하지 말랬잖아", "규칙 어겼네", "왜 X 했어"처럼 지적이 분명하면 따로 묻지 않는다.
- Claude가 스스로 규칙을 어겼다고 알아챘을 때. 응답을 보낸 뒤에 알아챈 것도 포함한다.

아래는 기록하지 않는다.

- 규칙에 없는 취향을 사용자가 새로 알려 준 경우. 규칙에 없으면 어긴 것이 아니다. 대신 어느 규칙에 넣으면 좋을지 한 줄로 제안한다.
- 코드 버그처럼 작업 결과물의 결함. 작업 방식이 규칙을 어긴 경우만 기록한다.

## 절차

1. 위반을 바로잡는 일을 먼저 한다. 기록은 그다음이다.
2. [`templates/ffc.md`](../../templates/ffc.md) 틀대로 써서 저장한다.
3. 저장한 뒤 경로를 한 줄로 알린다. 쓰기 전에 초안을 보여 주지 않는다.

한 세션에서 같은 규칙을 여러 번 어겼으면 파일을 새로 만들지 않고 기존 파일에 "잘못"과 "지적" 줄을 더한다.

## 저장 위치

`$FFC_PATH/{YYYY}/{MM}/{DD}-{HHmm}-{주제}.md`, `$FFC_PATH`는 [`rules/environments.md`](../../rules/environments.md)에 있다.

- 시각은 `date '+%Y %m %d %H%M'`로 얻은 로컬 시간이다.
- `{주제}`는 어긴 내용을 2~5단어로 줄여 붙임표로 잇는다. 예: `승인-없이-커밋`.
- 같은 이름의 파일이 있으면 덮어쓰지 않고 `-2`를 붙인다.
- 세션 ID는 `printenv CLAUDE_CODE_SESSION_ID`로 얻는다. 값이 없으면 `session` 줄을 지운다.

## 필드

| 필드      | 값                                                                                     |
| --------- | -------------------------------------------------------------------------------------- |
| `trigger` | 사용자가 지적했으면 `user`, Claude가 스스로 알아챘으면 `self`                          |
| `rule`    | 어긴 규칙의 파일 경로와 절 제목. 예: `rules/workflow.md#HOW TO WORK`. 모르면 비워 둔다 |

## 규칙

- 대화에 실제로 있었던 것만 적는다. 사용자의 지적은 원문 그대로 옮긴다.
- 잘못을 Claude에게 유리하게 줄여 쓰지 않는다.
- 비밀값, 토큰, 고객 데이터, 내부 URL, 개인정보는 적지 않는다. 필요하면 `<내부 URL>`처럼 가린다.
- 기록했다는 이유로 규칙이나 스킬 파일을 바로 고치지 않는다. 보강은 사용자가 요청할 때 한다.
