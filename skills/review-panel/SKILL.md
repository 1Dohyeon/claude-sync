# 리뷰 패널 절차

한 모델이 여러 영역을 한 컨텍스트에서 순차로 보면 앞 영역이 뒤 영역 판단에 섞인다. 이 절차는 영역별로
격리된 리뷰어를 병렬로 돌리고, 취합만 상위 모델이 한다. 아래 순서대로 진행한다.

## 리뷰 대상 확정

- **사용자가 리뷰 범위를 지정했으면 그것이 1순위다** — 커밋 범위(`<from> <to>`), 특정 커밋, 머지 커밋,
  "최근 머지" 같은 지시. 지정된 범위로 diff를 뜬다.
- 지정이 없으면 베이스 브랜치로 잡는다: `develop`이 있으면 `develop`, 없으면 `main`.
  - merge-base를 잡는다: `MB=$(git merge-base <베이스> HEAD)`.
  - 리뷰 대상 diff는 `git diff $MB` **하나**다 — 커밋된 변경과 워킹트리 미커밋(스테이징 포함)을
    라인 번호가 일관되게 한 번에 담는다. 두 개를 따로 떠서 합치지 않는다.
- 위 방법으로 잡은 diff가 비었으면 중단하고 그 사실만 보고한다.
- PR 번호를 받은 경우는 이 절차의 범위 밖이다 — 그 브랜치를 로컬로 가져오는 절차가 아직 없다. 사용자에게
  알리고, 해당 브랜치를 체크아웃해서 다시 요청하도록 안내한다.

## 규모 판단

- 로직이 있는 파일이 하나도 없으면(설정값·문구·주석·경로·문서 수정 등) 패널을 띄우지 않는다. 변경이
  여러 파일에 걸쳐도 마찬가지다. 관련된 한두 영역만 직접 간단히 보고 끝낸다.
- 그 외에는 병렬 호출로 간다.

## 병렬 호출

**한 응답에서** 서브에이전트 4개를 동시에 호출한다. 순차로 부르지 않는다.

- `architecture-reviewer`
- `logic-reviewer`
- `testing-reviewer`
- `convention-reviewer`

각 호출 프롬프트에 다음을 그대로 넘긴다.

- 위에서 확정한 diff 범위 (사용자 지정 범위, 또는 `MB=$(git merge-base <베이스> HEAD)` 뒤 `git diff $MB`).
  각 에이전트가 스스로 같은 범위로 diff를 뜬다.
- "자기 영역만 보고 다른 영역은 지적으로 세우지 말 것" — 각 에이전트 정의에 이미 있으나 한 번 더 못박는다.

## 취합

네 결과가 다 온 뒤에 한다. 이 단계에서 **새로운 지적을 만들지 않는다.**

- 같은 지적이 둘 이상 에이전트에서 나오면 하나로 합치고, 어느 영역들에서 나왔는지 적는다.
- 심각도로 정렬한다. 리뷰어마다 심각도 표기가 다를 수 있으니 전부 높음·중간·낮음으로 정규화한다.
- 에이전트 간 결론이 상반되면 **해소하지 말고 양쪽을 나란히 드러낸다** — 판단은 사용자 몫이다.

## 출력

마크다운 리포트 하나로 낸다. `ReportFindings` 도구는 쓰지 않는다.

- 영역별(아키텍처 / 코드 레벨 / 테스트 / 컨벤션)로 묶고, 그 안에서 심각도 순으로 나열한다.
- 각 항목은 위치(`file:line`), 문제, 제안. logic 항목은 실패 시나리오를 포함한다.
- 영역에 지적이 없으면 "지적 없음"으로 표기하고 그 영역이 무엇을 확인했는지 한 줄 남긴다.
- 마지막에 에이전트 간 상반된 결론이 있었으면 따로 모아 적는다.
