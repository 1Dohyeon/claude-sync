# 커밋

## 커밋 단위

PR 구조(단일 PR, 순차 PR, 부모 PR + 하위 PR)는 계획 단계에서 정한다. 판정 기준과 파일 세는 방식은 [`dev-plan/sub/analyze-task.md`](../dev-plan/sub/analyze-task.md)의 "규모"와 "PR 구조"에 있다.

| 규칙                     | 내용                                                                          |
| ------------------------ | ----------------------------------------------------------------------------- |
| 논리적 변경 하나         | 메시지를 "그리고" 없이 한 문장으로 쓸 수 없으면 나눈다                        |
| 커밋마다 통과            | 각 커밋 시점에 빌드와 타입 검사가 통과해야 한다                               |
| 구조와 동작 분리         | 이름 바꾸기·이동·추출과 동작 변경을 섞지 않는다. 지역 변수 이름 정도는 예외다 |
| 테스트 동봉              | 동작을 바꾸는 커밋에는 그 동작의 테스트를 함께 담는다                         |
| 같은 PR 안에서 생긴 결함 | 원래 커밋에 `fixup`으로 합치지 않고, `fix` 커밋으로 새로 남긴다               |

- trivial 작업은 대부분 커밋 하나가 곧 PR 하나다.
- trivial인데 커밋이 여러 개로 나뉘면, 관계없는 변경이 섞였다는 신호로 보고 PR을 나눈다.
- 사유(`fix` 커밋): 리뷰 뒤에 고친 내용이 별도 커밋으로 남아야, 다시 리뷰할 때 그 수정만 증분으로 볼 수 있다.

## 커밋 메시지

1. commit/git 관련 문서(`CONTRIBUTING.md`, `.github/` 안의 문서, 저장소 `CLAUDE.md` 등)가 있으면 Read한다.
2. `git log`로 기존 커밋 히스토리를 보고 실제 쓰이는 패턴을 파악한다.

**제목**: 저장소에 규칙 문서가 없으면 1번에서 파악한 히스토리 패턴을 따른다.

**본문(description)**: 저장소에 규칙이 있으면 그 규칙을 따른다. 없으면(대체로 없다) 다음을 따른다.

- 1레벨 불릿 리스트로 구성한다.
- why(이유)는 적지 않는다. what(무엇을 했는지)만 적는다.
