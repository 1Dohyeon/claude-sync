# 지시문 템플릿

[`orca-worker.md`](orca-worker.md)의 "3. worker 실행"에서 `--spec-file`로 넘길 지시문이다. worker는 이 지시문과 거기서 가리킨 문서만 보고 일한다.

- 계획 문서가 있으면 "계획이 있을 때"를 쓴다. 계획이 없을 때만 "계획이 없을 때"로 지시를 모두 적는다.
  - 사유: 계획 내용을 지시문에 옮겨 쓰면, 계획 문서가 바뀌어도 사본은 따라 바뀌지 않는다.
- `<...>`를 채우고, 해당 없는 줄은 지운다.

## 계획이 있을 때

```markdown
# 작업: <제목>

## 작업 위치

새 worktree나 브랜치를 만들지 않는다.

- worktree: <dir>
- 브랜치: <branch>
- 베이스: origin/<base>

## 할 일

- 계획 문서: <계획 문서 폴더 경로>
- 맡을 태스크: <태스크 번호 범위>

## 규칙

- 시작 전에 저장소 규칙(CLAUDE.md, rules/ 등 저장소가 정한 문서)과 계획 문서를 읽고 따른다.
- 수정은 /dev, 커밋은 /git-commit 규칙대로 한다. 1레벨 태스크마다 커밋한다.
- 너는 맡겨진 worker이므로 /dev의 "위임"을 적용하지 않는다. worker나 서브에이전트에게 다시 맡기지 않고 직접 구현한다.
- 고칠 파일은 각 태스크의 `파일:` 줄 안으로 한정한다.
- 로컬 커밋까지만 한다. push하지 않는다.
- 계획 문서는 고치지 않는다. 계획으로 답이 서지 않는 점은 임의로 정하지 않고 coordinator에게 묻는다.

## 보고

worker_done으로 아래를 보낸다.

- 끝낸 태스크 번호
- 커밋 해시와 메시지
- `git status -sb` 출력
- 확인 결과(실패하거나 건너뛴 것 포함)
- 판단이 필요했던 점
```

## 계획이 없을 때

```markdown
# 작업: <제목>

## 작업 위치

새 worktree나 브랜치를 만들지 않는다.

- worktree: <dir>
- 브랜치: <branch>
- 베이스: origin/<base>

## 배경

<왜 하는지, 사용자와 정한 것>

## 할 일

1. <할 일>
2. <할 일>

## 규칙

- 시작 전에 저장소 규칙(CLAUDE.md, rules/ 등 저장소가 정한 문서)을 읽고 따른다.
- 수정은 /dev, 커밋은 /git-commit 규칙대로 한다.
- 너는 맡겨진 worker이므로 /dev의 "위임"을 적용하지 않는다. worker나 서브에이전트에게 다시 맡기지 않고 직접 구현한다.
- 로컬 커밋까지만 한다. push하지 않는다.
- 지시로 답이 서지 않는 점은 임의로 정하지 않고 coordinator에게 묻는다.

## 확인

- <저장소의 검증 명령, 이 작업에서 특히 볼 것>

## 보고

worker_done으로 아래를 보낸다.

- 바꾸거나 만든 파일
- 커밋 해시와 메시지
- `git status -sb` 출력
- 확인 결과(실패하거나 건너뛴 것 포함)
- 판단이 필요했던 점
```
